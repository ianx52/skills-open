# 通用配图生成大师 Skill v5.1.0

> **v5.0.0 核心升级**：从"实战操作系统"升级为"**质量锚点系统**"。v4.0.0解决了"文字错字、封面平淡、隐喻太浅"三个表层问题，但质量仍不稳定——根因是**每次画图都从零自由发挥，没有"已知的好"作为锚点**。v5.0.0 吸收公众号配图体系（gzh-illustration v1.3.4，20+轮实战迭代验证）的精华，建立六大质量锚点：**段落骨架五层核对 → 视觉隐喻设计卡 → 构图模板库+参考图驱动 → 内容类型映射 → 三轮打磨SOP → 统一交付形态**。叠加头条已有的中文防错系统+封面竞争力设计+返工策略库，让"超高质量"从碰运气变成每次可复现。
>
> **本次升级的实战来源**：公众号配图体系（H20/GPT-6 Astra等多篇，20+轮迭代）已固化的"定稿版方法论+6张参考图"，与头条v4.0.0（英伟达收购HF长文3轮迭代）融合。

## 🚨 执行铁律（每次调用必读，违反视为违规）

> **本skill的核心不是"方法论"，而是"纪律"。方法论写得再好，Agent不执行=0。**

### 每次画图，必须严格执行以下五步，缺一不可：

**第1步：画前重读（禁止凭记忆）**
- 调用本skill后，必须先重新读取「10项必选元素清单」「中文文字防错系统」「构图模板库」
- 禁止只凭记忆或印象生成，必须基于刚读到的清单逐项组织prompt
- 即使上次刚画过，每次调用都必须重读（上下文会滚动压缩，记忆不可靠）

**第2步：读正文+五层核对（v5.0.0新增，正文图硬门槛）**
- 每张正文图生成前，必须先读它对应的那一段正文
- 提取"信息骨架"，按「二、段落骨架五层核对法」逐层核对（数据/来源/性质/判断/限定）
- **任何一层缺失先补齐再画，不能凭"大概"画**

**第3步：填设计卡+选模板（v5.0.0新增，写prompt之前必做）**
- 按「三、视觉隐喻设计卡」填写6项（核心隐喻/构图模板/信息布局/小黑动作/参考图/水彩质感）
- 按「四、构图模板库」选1种模板，**生成时必须传入对应模板的参考图**
- **设计卡缺失=禁止生成；参考图不传=禁止生成**

**第4步：画前打勾（生成前逐项确认）**
- 生成图片前，必须把10项必选元素**逐项列出并写进prompt**
- 同时必须执行「中文文字防错检查」（见第一节）
- 检查清单全部打勾后才允许调用生图工具

**第5步：画后验收+打磨（生成后逐项对照）**
- 图片生成后，必须对照验收清单逐项检查
- **中文文字必须逐字核对**（最高优先级验收项）
- **必须走三轮打磨SOP**（见「八、打磨SOP标准化」）：第1轮结构打磨→第2轮细节打磨→第3轮精修（可选）
- **禁止一次生成就交付**——文字对只是及格线，画面质量四维度全过才是交付线
- 返工最多3次，仍不合格必须停下来重新检查prompt设计问题
- 每张图验收通过后，向用户明确标注"已按skill v5.0.0标准验收"

**违规示例（明令禁止）**：
- ❌ 不重读skill直接生成
- ❌ 凭印象生成，漏掉小黑/颜色/风格
- ❌ 不读正文、不做五层核对直接画
- ❌ 不填设计卡、不选模板、不传参考图直接生成
- ❌ 生成后发现中文错字但嫌麻烦不返工
- ❌ 一次生成就交付，不做三轮打磨
- ❌ 用"差不多就行"的心态验收
- ❌ 在prompt中写注音说明/字形拆解（会被画进图里）

## 一、中文文字防错系统（v4.0.0保留，最高优先级）

> **为什么这是最高优先级**：v3.1.1在实战中中文文字错字率超过60%。"卖铲子"→"卖骰子"→"卖锚子"（连续3次才成功）、"留心眼"→"真心眼"、"难"→"滩"、"分发权"→"分股权"、"2027交割见分晓"→"交职院分晚"。生图模型（seedream）对中文字符的生成能力有限，这是硬限制，必须通过方法论适配。

### 1.1 易错字黑名单（生成前必须检查）

以下字/词在生图模型中极易写错，prompt中出现时必须特别处理：

| 易错字/词 | 常见错误 | 处理方式 |
|-----------|---------|---------|
| 铲子 | 骰子、锚子、铲子 | 避免使用，改用"工具""家伙" |
| 留心眼 | 真心眼 | 避免使用，改用"多留神""要小心" |
| 难（结尾） | 滩、摊 | 避免在句尾单独用"难"，改用"不容易""不简单" |
| 分发权 | 分股权、分配权 | 避免使用，改用"说了算""有话语权" |
| 管矿 | 管广、管矿 | 避免使用，改用"管矿山""做矿主" |
| 交割 | 交职、交割 | 避免使用，改用"完成""落地" |
| 见分晓 | 分晚、分晓 | 避免使用，改用"见结果""看结局" |
| 承诺 | 承落、承诺 | 可用，但需在prompt中强调 |
| 开放 | 开方、开放 | 可用，但需在prompt中强调 |
| 收购 | 收够、收购 | 可用，但需在prompt中强调 |
| 算力 | 算利、算力 | 可用，但需在prompt中强调 |
| 开发者 | 开法者、开发者 | 可用，但需在prompt中强调 |

**核心原则**：能不用易错字就不用，改用同义的简单字。金句/数据卡/判断标签的文字必须经过"易错字检查"后才能写入prompt。

### 1.2 文字长度限制（硬性约束）

生图模型对短文字的生成准确率远高于长文字。必须遵守：

| 文字类型 | 最大长度 | 推荐长度 | 示例 |
|---------|---------|---------|------|
| 金句（红色） | 8字 | 4-6字 | "买了个承诺""从卖铲子到管矿" |
| 数据卡（橙色） | 6字 | 2-4字 | "129.3亿""1800万""3倍" |
| 判断标签（蓝色） | 6字 | 2-4字 | "史上第二""拒绝收购难"→改为"不容易" |
| 编号（左上角） | 2字 | 1字 | "一""二""封面" |
| 封面主标题 | 10字 | 6-8字 | "877亿买了个承诺" |

**超过长度的文字必须拆分或简化**。例如"2027年上半年交割见分晓"→拆为数据卡"2027"+判断标签"待审批"。

### 1.3 Prompt 逐字强调技巧（核心方法论）

当必须使用可能易错的文字时，在prompt中使用以下技巧提高准确率：

**技巧1：文字单独成段，不与视觉描述混在一起**
```
❌ 错误写法：
画面中间有一个橙色数据卡片，上面写着"129.3亿美元"，旁边有小黑指着它

✅ 正确写法：
画面中间有一个橙色圆角矩形数据卡片。
卡片上的文字是：129.3亿
（文字必须清晰、准确、无错别字）
```

**技巧2：朴素写法——不加任何元指令（v5.1.0修正，重要！）**
实测：在文字后加括号元指令（"这4个字必须准确无误""文字必须清晰准确"）会被模型**直接画进图里**，形成污染文字。
```
❌ 错误写法（实测图上出现"买的是位置(这5个字准确无误…)"）：
画面顶部红色大字，文字内容是：买的是位置（这5个字必须准确无误，每个字都要写对）

✅ 正确写法（朴素写法）：
画面顶部红色大字，文字内容是：买的是位置
```
**铁律**：文字只给准确文本，后面不加任何括号、说明、指令。

**技巧3：避免在同一张图中出现过多文字**
- 每张图最多3处文字（1金句+1数据卡+1判断标签）
- 文字越少，准确率越高
- 目录导览等长文字**禁止出现在封面**（实战中100%乱码）

**技巧4：数字用阿拉伯数字，不用中文数字**
```
❌ "一百二十九亿三千万美元"
✅ "129.3亿"
```

**技巧5：文字白名单铁律（v5.1.0新增，公众号已验证有效，防一切污染文字的最终防线）**
prompt末尾必须加一个【文字白名单】块，把整图允许出现的文字全部列出：
```
【文字白名单】
整图只允许出现以下文字：买的是位置、45亿、129.3亿、3倍、收购价、890亿、单季收入、2023、2026、NVIDIA、还没赚钱、史上第二。除此之外禁止出现任何其他文字、数字、字母、符号。
```
实测效果：白名单+朴素写法组合下，12处文字的图可以做到全部正确；不加白名单时模型自由发挥污染严重（章节标题、结构词、说明文字都会被画进去）。

### 1.4 固定乱码模式库（已知问题，必须规避）

以下是seedream模型的固定乱码模式，prompt中必须规避：

| 模式 | 表现 | 规避方法 |
|------|------|---------|
| "8%" | 任何包含"8%"的文字都会乱码 | 避免使用"8%"，改用"8个百分点"或纯数字"8" |
| 目录导览 | 封面底部的5个小标题100%乱码 | 封面禁止目录导览，改用3个数据卡横排 |
| 注音说明 | prompt中写"XX字，读YY"会被画进图里 | 绝对禁止在prompt中写注音/拼音/字形拆解 |
| 色值编号 | "#FB8C00"会被画在卡片上 | 色值只用于指定颜色，禁止作为文字内容 |
| 长句金句 | 超过8字的金句错字率>80% | 金句控制在6字以内 |
| 章节标题泄漏（v5.1.0） | prompt中的【来源】【限定】等章节标题被画成"来源：限定" | 章节标题只用【画面内容】【金句】【标签】【角色】等安全词；来源/限定并入【画面内容】描述，不单独开章节 |
| 结构性词泄漏（v5.1.0） | "左组/右组"被画成"主租" | 用"画面左半部分/画面右半部分"描述 |
| 括号元指令泄漏（v5.1.0） | "（文字必须准确）（放在底部）"被画进图 | 一律删除所有括号说明，用朴素写法 |
| 来源错字（v5.1.0） | "官方博客"→"官方微博/助力博睿""英伟达官网"→"英迪进入官网" | 来源标注易错率高，头条正文图**默认不画来源**（五层核对保留为生成前核对，来源在图注/正文体现）；必须画时用最短形式"NVIDIA" |
| 自动加标点（v5.1.0） | "还没赚钱"→"还没赚钱！/？" | 负面提示词加"文字后面不要加标点符号" |

### 1.5 文字生成失败的修正策略

| 失败类型 | 表现 | 修正方法 |
|---------|------|---------|
| 单字错误 | "铲子"→"骰子" | 换同义字（"工具"），或在prompt中逐字强调 |
| 多字乱码 | "见分晓"→"分晚" | 缩短文字或拆分 |
| 完全不显示 | 金句位置空白 | 检查prompt中金句是否单独成段，重新生成 |
| 元信息泄漏 | 图底部出现注音说明 | 删除prompt中的所有注音/拼音/字形拆解说明 |
| 数字错误 | "129.3亿"→"1293亿" | 用阿拉伯数字+单位，在prompt中强调小数点 |
| 章节/结构词泄漏（v5.1.0） | 图上出现"来源：""限定""主租" | 删除对应章节标题和结构词，改写描述 |
| 文字被加标点（v5.1.0） | "还没赚钱"→"还没赚钱！" | 负面词加"不加标点"；如已生成，用image_edit去除小区域标点（有效） |
| 来源错字反复（v5.1.0） | 多次生成来源都错 | 停止重试，直接去掉图上来源标注，来源写入图注 |

## 二、段落骨架五层核对法（v5.0.0新增，正文图质量硬门槛）

> **为什么必须有这一节**：一张正文图"好看"不等于"合格"。正文图必须忠实覆盖它所对应的那段正文的信息骨架，否则就是装饰。**判定一张正文图质量的标准，不是画面漂不漂亮，而是它把该段的核心信息讲全了没有——只能高不能低。**

**每张正文图生成前，先读它对应的那一段正文，提取"信息骨架"，按五层逐层核对：**

| 层 | 核对什么 | 通用示例（不照搬具体文章） |
|----|---------|--------------------------|
| **数据层** | 该段的核心数字/比例是否都上图？**带单位（%等）**？关键数据是否**带时间节点**（如"3月最强""9月发布"）？ | 45亿→129.3亿，1800万开发者，3年涨约3倍，时间2023→2026 |
| **来源层** | 关键数据/事件是否标注**来源**（平台名/机构名/官方口径）？ | NVIDIA官方博客、36氪、新浪财经 |
| **性质层** | 该段的机制/概念本质，是否用**图形（场景隐喻）+ 判断标签**表达？ | 收费站=收算力税、保险箱=黑箱不可读 |
| **判断层** | 该段的核心判断是否**成句**（标题/金句）？ | "877亿买了个承诺""从卖铲子到管矿" |
| **限定层** | 是否有**对冲/限定**（"这只是开始""真实世界更复杂"类）？防止只呈现单面、让读者被数字带走 | "承诺是承诺，落地是落地" |

**判定规则**：五层任一缺失 → 不合格，补齐再交付。这就是"每张图质量只能高不能低"的硬门槛。

**来源标注规范（来源层落地）**：
- 关键数据/事件必须带来源：平台名/机构名/官方口径，灰色小字放画面下方
- 数据一律带单位（% 等）；关键数据带时间节点
- 头条可简化（不强制英文原名），但"来源：XXX"必须有
- 这符合账号"来源可查"基因，是"判断提供者"的信任背书

**跨越式大对比设计原则（吸引力×密度兼得）**：
- 正文图主视觉**优先用"跨越式大对比"**：被划掉的旧值 → 巨大箭头 → 新值，旁边补参照值（如"3年涨3倍"）
- **禁止"独占大数字"**（一个超大数字占画面 40%，会牺牲信息密度——公众号实测被用户否决）
- 吸引力靠"跨越幅度"（45亿→129.3亿的反差），密度靠"多数据点 + 来源 + 判断 + 限定"共存

## 三、视觉隐喻设计卡（v5.0.0新增，写prompt之前必做！）

> **为什么要有设计卡**：直接写prompt=元素平铺，模型不会设计隐喻。必须在写prompt之前，先完成"视觉隐喻设计"——这张图用什么核心隐喻？信息怎么融入隐喻？小黑在叙事中扮演什么角色？设计卡填完才能写prompt。

**每张正文图写prompt之前，必须填以下设计卡**：

```
图序号：
对应正文段落：
【1. 核心隐喻】用什么物理物件/动作表达本段的抽象概念？
  （例：滚雪球=估值暴涨、收费站=收算力税、特洛伊木马=承诺背后有锁、钥匙=控制权）
【2. 构图模板】从「四、构图模板库」5种模板选1种（写明模板编号）
【3. 信息布局】金句/数据/判断/来源分别放在画面哪个位置？
  （必须融入隐喻，不能贴在旁边）
【4. 小黑动作】小黑在这个隐喻叙事中扮演什么角色？做什么具体动作？
  （必须参与核心动作，不是站旁边装饰）
【5. 参考图】传入对应模板的参考图（assets/reference-layouts/模板X-*.jpg）
【6. 水彩质感】明确要求"水彩填色有笔触有层次，不平涂"
```

**设计卡铁律**：
- 核心隐喻必须与内容相关，不能为了隐喻而隐喻
- 信息必须融入隐喻（如数据放在路径节点上、判断标签放在隐喻物件旁），不能元素平铺
- 小黑必须在叙事中有具体动作（如"试图打开保险箱""在迷宫出口思考""坐在电脑前敲键盘"），不能"站在旁边"
- 设计卡填完才能写prompt；**设计卡缺失=禁止生成**

## 四、构图模板库（v5.0.0新增，高质量配图自动化的关键）

> **为什么要有构图模板**：实测发现，"信息对"只是及格线，"构图有设计感+视觉隐喻统一"才是高质量线。自由生成的图往往元素平铺、隐喻浅、信息密度低。从公众号定稿版5张图提炼出5种高质量构图模板（16:9正文图，头条直接复用），每张图必须先选模板再填内容，**禁止自由发挥构图**。生成时必须传入对应模板的参考图，让模型学习构图骨架、水彩质感、元素融合方式。

**5种构图模板（每种有参考图）**：

### 模板1：双组并排对比型
- **参考图**：`assets/reference-layouts/模板1-双组并排对比型.jpg`
- **骨架**：左右两组"旧值被红斜线划掉 → 红色箭头 → 新值"并排，下方一组辅助对比（如时间/成本）
- **适用场景**：有两组以上数据对比的段落（如两个维度的变化、两个测试的提升）
- **元素布局**：左组对比（旧→新） | 右组对比（旧→新），下方辅助对比，小黑在左侧参与核心动作（如敲电脑/指屏幕）
- **关键**：每组对比必须有"旧值被划→箭头→新值"的完整结构，不能只放单个数字
- **信息密度**：高（至少2组主对比+1组辅助对比）

### 模板2：路径穿越隐喻型
- **参考图**：`assets/reference-layouts/模板2-路径穿越隐喻型.jpg`
- **骨架**：一条视觉路径（红色上升箭头/道路/河流）从旧值出发，穿越一个核心隐喻物件（迷宫/门/关卡/隧道），到达新值
- **适用场景**：有"从A到B的突破/成长/跨越"叙事的段落（如估值从45亿到129.3亿、能力从弱到强）
- **元素布局**：旧值(左下，被划) → 路径上升 → 隐喻物件(中) → 新值(右上)，参照值在旁，小黑在隐喻物件旁参与动作（如思考/指向）
- **关键**：路径本身就是视觉隐喻（成长/突破），不是简单的箭头连接；隐喻物件必须与内容相关（迷宫=陌生环境、门=突破、关卡=挑战）
- **信息密度**：高（旧→新对比+参照值+隐喻物件+限定对冲）

### 模板3：三格漫画演变型
- **参考图**：`assets/reference-layouts/模板3-三格漫画演变型.jpg`
- **骨架**：三格并列，每格一个场景+底部标签，表达从坏状态→中间态→好状态的演变
- **适用场景**：有"状态进化/对比/三种模式"叙事的段落（如AI从工具到同事、三种协作模式、过去/现在/未来）
- **元素布局**：格1(坏状态，标签) | 格2(中间态，标签) | 格3(好状态+数据卡，标签)，小黑在每格中扮演不同状态
- **关键**：三格必须有清晰的演变逻辑（不是三个独立场景）；数据卡嵌入第三格（好状态），不单独堆放
- **信息密度**：高（三个场景+演变逻辑+数据+判断）

### 模板4：左右分割+隐喻型
- **参考图**：`assets/reference-layouts/模板4-左右分割隐喻型.jpg`
- **骨架**：左侧数据对比区（2组"旧→新"对比），右侧核心隐喻物件+小黑动作，中间可用分割线或留白分隔
- **适用场景**：数据+抽象概念并存的段落（如数据下降+黑箱概念、数据上升+监督难度、买下平台+开放承诺）
- **元素布局**：左(2组数据对比，上下排列) | 右(隐喻物件+小黑试图操作/打开/观察)，判断标签在底部
- **关键**：隐喻物件必须表达抽象概念（保险箱=不可读/黑箱、锁=难监督、墙=障碍、柜台=中立）；小黑必须与隐喻物件互动（不是站旁边）
- **信息密度**：高（2组数据对比+隐喻物件+判断+来源）

### 模板5：角色演变+清单型
- **参考图**：`assets/reference-layouts/模板5-角色演变清单型.jpg`
- **骨架**：上方角色演变（A形态→红色大箭头→B形态），下方左=行动清单（白框），下方右=数据卡
- **适用场景**：有"角色/身份/能力转变"+行动清单的段落（如从卖铲子到管矿、从依赖到自主、从工具到平台）
- **元素布局**：上(A形态角色 | 箭头 | B形态角色)，下左(行动清单白框，①②③)，下右(数据卡2张)
- **关键**：A/B形态必须有明显视觉差异（道具/服装/姿态），不能只是同一个角色换位置；清单用白框/卡片承载，不散落
- **信息密度**：高（角色演变+行动清单+数据卡+判断）

**模板选择规则**：
1. 有2组以上数据对比 → 模板1或模板4
2. 有"从A到B突破"叙事 → 模板2
3. 有"三种状态/模式演变" → 模板3
4. 有"角色转变+行动清单" → 模板5
5. 一篇文章5张图尽量用不同模板，避免重复构图
6. 模板不够用时可创造新模板，但必须经过用户确认后入库

## 五、内容类型→模板映射 + 模板扩展机制（v5.0.0新增）

> **为什么要有映射表**：5种模板是从定稿版提炼的，换一篇文章（方法步骤文/趋势预测文/人物分析文）可能不知道选哪个模板。本章节提供"内容类型→模板"映射表和决策树，以及模板不够用时的扩展机制。

### 5.1 内容类型→构图模板映射表

| 内容类型 | 首选模板 | 备选模板 | 说明 |
|---|---|---|---|
| 多组数据对比/提升 | 模板1双组并排对比 | 模板4左右分割 | ≥2组"旧→新"对比用模板1；数据+抽象概念并存用模板4 |
| 能力突破/成长/跨越 | 模板2路径穿越隐喻 | 模板1双组对比 | 有"从A到B突破"叙事用模板2；只有数据没有隐喻物件退化为模板1 |
| 三种状态/模式演变 | 模板3三格漫画 | 模板5角色演变 | "坏→中→好"或"A/B/C三种模式"用模板3 |
| 数据+抽象概念并存 | 模板4左右分割 | 模板1双组对比 | 左侧数据对比+右侧隐喻物件用模板4 |
| 角色转变+行动清单 | 模板5角色演变清单 | 模板3三格漫画 | "从X到Y的角色转变"+清单/方法用模板5 |
| 方法/步骤/流程 | 模板3三格漫画（步骤格） | 模板2路径穿越 | 三步法=三格；多步骤=路径上的节点 |
| 趋势/预测/未来 | 模板2路径穿越 | 模板4左右分割 | 路径=走向未来；左右=现在vs未来 |
| 对比/选择/权衡 | 模板1双组并排 | 模板4左右分割 | 两种选项并排对比 |
| 问题→原因→解法 | 模板3三格漫画 | 模板2路径穿越 | 三格=问题/原因/解法 |
| 单一核心概念解释 | 模板4左右分割 | 模板2路径穿越 | 左侧概念解释+右侧隐喻物件 |

### 5.2 模板选择决策树（按顺序判断）

1. 这段有**≥2组数据对比**吗？
   - 有 → 有抽象概念/隐喻物件吗？→ 有→**模板4**，没有→**模板1**
   - 没有 → 继续
2. 这段有**"从A到B突破/成长"叙事**吗？→ 有→**模板2**
3. 这段有**三种状态/模式/步骤**吗？→ 有→**模板3**
4. 这段有**角色转变+行动清单**吗？→ 有→**模板5**
5. 都不符合 → **创造新模板**（见5.3）

### 5.3 模板扩展机制（5种模板不够用时怎么办）

当5种模板都不适合当前内容时，按以下流程创造新模板：

1. **分析内容结构**：这段内容的核心结构是什么？（如"环形循环""金字塔层级""时间线长图""辐射发散"）
2. **设计骨架**：写出新模板的骨架描述（元素布局/分区/视觉重心/适用场景）
3. **生成样张**：用新模板生成1张样张，验证构图是否成立、信息是否能融入
4. **用户确认**：给用户看样张，确认这个新模板是否可用、是否值得入库
5. **入库**：用户确认后，把样张复制到 `assets/reference-layouts/模板N-XXX型.jpg`，在「四、构图模板库」中新增模板描述
6. **更新映射表**：在「五、内容类型→模板映射」中新增这个模板对应的内容类型

**新模板命名规则**：模板N-描述性名称型.jpg（如"模板6-环形循环型""模板7-金字塔层级型"）

**铁律**：创造新模板必须经过用户确认，不能AI自己决定入库。入库后所有后续文章都可复用。

## 七、封面竞争力设计（v4.0.0保留 + v5.0.0升级钩子三法）

> **为什么封面需要独立方法论**：封面在头条信息流中的竞争逻辑与正文配图完全不同。封面只有3秒抓眼球的机会，正文配图是辅助阅读。v3.1.1把两者用同一套方法论，导致封面太平淡（第一版封面"两扇门+钥匙"被用户否决）。

### 7.1 头条封面规范（3:4竖版）

| 项目 | 规范 | 理由 |
|------|------|------|
| 比例 | 3:4竖版 | 头条信息流大图卡片，3:4展示面积最大，最抓点击 |
| 尺寸 | 1536x2048 | 3:4的标准高清尺寸 |
| 安全区域 | 中心1200x1600 | 重要信息放在中心，边缘留裁剪空间 |
| 文字数量 | 最多3处（1主标题+2数据卡） | 文字越少越抓眼，错字率越低 |
| 主标题长度 | ≤10字 | 信息流中一眼能读完 |
| 数据卡数量 | 1-3个横排 | 用数字制造冲击力 |

### 7.2 封面核心原则（v5.0.0升级，6条）

1. **封面=钩子，不是总结**——目标是制造冲突感让人点进来，不是概括全文内容
2. **反常识优先**——大家都在说A，你说"别只看A，真正重要的是B"，用红斜线划掉A指向B
3. **极简**——一张封面只讲一个钩子，不超过3个视觉元素（数字/箭头/关键词），不杂乱
4. **高对比**——深色底（近黑/深蓝黑）或场景化视觉（动态+冲突），视觉冲击力强
5. **场景化封面可放小黑/大手等视觉元素**（头条特色，区别于公众号纯信息图）——但要参与核心动作，不是装饰
6. **安全区铁律**——所有关键信息在中央60%，左右各留≥15%安全边距

### 7.3 封面钩子设计三法（v5.0.0新增，从公众号迁移）

**法1：反常识划掉法（最常用）**
- 结构：顶部小字引语 → 中间超大数字/概念被红斜线划掉 → 红色箭头 → 底部超大关键词
- 逻辑：把大家都在吹的东西划掉，指向真正重要的东西
- 示例："欢迎来到AGI时代？" → 99.9被划掉 → 干活
- 适用：有"大众误区 vs 真正重点"的文章
- 头条示例："英伟达877亿买HF？" → "买入口"被划掉 → "买承诺"

**法2：对比冲突法**
- 结构：左侧旧值/错误认知被划掉 → 右侧新值/真相，中间箭头或VS
- 逻辑：两个极端对比，制造冲击力
- 示例：45亿→129.3亿、以前→现在、依赖→自主
- 适用：有强烈数据对比或认知反转的文章

**法3：大数字钩子法**
- 结构：超大数字居中 + 一行副标题，数字本身就是钩子
- 逻辑：用惊人数字吸引注意力
- 示例："877亿"居中+"买了个承诺"副标题
- 适用：有单个惊人数字的文章

### 7.4 封面三要素（缺一不可，v4.0.0保留）

**要素1：视觉冲击（第一眼抓住）**
- 必须有一个"大到占画面40%以上"的核心视觉元素
- 必须有动态感（手在撕、门在开、雪球在滚）
- 必须有颜色对比（红金撞色、明暗对比）
- 反例：两扇门+钥匙（静态、平淡、无冲击）
- 正例：巨手撕告示+门缝金光（动态、冲突、有冲击力）

**要素2：反常识钩子（让人想点）**
- 主标题必须是反常识/有悬念/有冲突的判断
- 不是"英伟达收购Hugging Face"（新闻标题，没人想点）
- 而是"877亿买了个承诺"（反常识，让人想点进去看"什么承诺"）
- 钩子公式：大数字+反常识判断 = 点击欲

**要素3：数据背书（建立可信度）**
- 1-3个数据卡横排在画面底部或中部
- 数据必须是文章中最有冲击力的数字
- 例如："129.3亿""1800万开发者""3年涨3倍"
- 数据卡用橙色，与红色主标题形成颜色层次

### 7.5 封面构图模板（v5.0.0新增，3种）

| 模板 | 结构 | 参考图 | 适用场景 |
|---|---|---|---|
| 封面A·划掉指向型 | 顶部小字→中间超大数字被红叉划掉→红色箭头→底部超大关键词 | `assets/reference-layouts/头条封面参考-巨手撕告示3比4.png` | 反常识/认知反转 |
| 封面B·左右对比型 | 左侧旧值被划掉→箭头→右侧新值，副标题在顶或底 | （待头条定稿后入库） | 数据对比/前后变化 |
| 封面C·大数字钩子型 | 超大数字居中+一行副标题，极简 | （待头条定稿后入库） | 单个惊人数字 |

**参考图驱动**：生成封面时，若现有参考图适用则传入；若题材需要新构图，按封面SOP生成样张→用户确认→入库，逐步积累头条自己的封面参考图库。

### 7.6 封面SOP（7步，v5.0.0升级）

1. **提炼反常识点**：从正文找"大家在说什么？真正重要的是什么？"——这是封面钩子的核心
2. **选钩子类型**：反常识划掉法/对比冲突法/大数字钩子法（三选一）
3. **选构图模板**：对应封面A/B/C，或场景化设计（大手/雪球/钥匙等动态视觉）
4. **写封面prompt**：按6.1封面Prompt模板（深色底或场景化+极简3元素+安全区+文字白名单）
5. **生成+验收**：安全区检查（关键信息在中央60%）+文字准确+视觉冲击力+钩子是否成立
6. **封面竞争力检查清单**（见7.7）
7. **交付**：最终版作为头条封面参考图入库（逐步积累头条封面参考图库）

### 7.7 封面竞争力检查清单（v4.0.0保留）

生成封面后，必须逐项检查：

- [ ] **1. 3秒测试**：遮住标题，只看画面，3秒内能猜出文章主题吗？
- [ ] **2. 视觉冲击**：核心元素占画面40%以上吗？有动态感吗？
- [ ] **3. 反常识钩子**：主标题是反常识/有悬念的判断吗？不是新闻标题吧？
- [ ] **4. 数据背书**：有1-3个数据卡吗？数据是文章中最有冲击力的吗？
- [ ] **5. 颜色对比**：有红金撞色或明暗对比吗？不是平淡的单色吧？
- [ ] **6. 文字准确**：主标题和数据卡的文字逐字核对了吗？没有错字吧？
- [ ] **7. 无目录导览**：封面没有目录导览吧？（实战中100%乱码）
- [ ] **8. 安全区**：所有关键信息在中央60%，左右15%安全边距无关键信息吗？
- [ ] **9. 3:4竖版**：尺寸是3:4竖版吗？不是16:9横版吧？
- [ ] **10. 信息流测试**：想象这张封面出现在头条信息流里，你会点吗？

### 7.8 封面设计模板库（v4.0.0保留）

**模板A：手撕型（适合收购/合并/决裂类题材）**
- 核心视觉：一只大手正在撕某物（告示/合同/大门）
- 动态感：撕的动作+被撕物的裂缝+裂缝透出的光
- 主标题："[大数字]买了个[反常识词]"
- 数据卡：交易金额+被收购方规模+估值涨幅

**模板B：雪球型（适合增长/复利/滚雪球类题材）**
- 核心视觉：一个小雪球从山坡滚下，变成巨大雪球
- 动态感：滚动轨迹+越来越大的雪球+飞溅的碎片
- 主标题："[小数字]→[大数字]，[时间]翻了[倍数]"
- 数据卡：起点数字+终点数字+涨幅倍数

**模板C：钥匙型（适合控制权/话语权/选择权类题材）**
- 核心视觉：左边钥匙挂在别人腰间，右边铁砧上自己打造钥匙
- 对比感：左右对称+依赖vs自主的对比
- 主标题："[反常识判断]，钥匙在谁手里？"
- 数据卡：依赖方规模+自主方进展+时间节点

**模板D：特洛伊木马型（适合陷阱/伪装/表里不一类题材）**
- 核心视觉：一个告示牌/礼物盒，裂缝里透出大锁/芯片/钩子
- 悬念感：表面美好+内里隐藏的危险
- 主标题："[表面好词]背后，藏着[反面词]"
- 数据卡：表面规模+隐藏代价+时间节点

**模板E：窗桥型（适合危机/转机/破局类题材）**
- 核心视觉：一扇门关了，但墙上有窗；路跨深沟变成桥；脚印旁有火把
- 希望感：困境中的出路+后来人的指引
- 主标题："关了一扇门，开了[数字]扇窗"
- 数据卡：困境规模+出路数量+时间节点

## 八、打磨SOP标准化（v5.0.0新增，每轮磨什么标准化）

> **为什么要有这一节**："多轮打磨至少2轮"是模糊的——AI每次凭感觉磨，可能磨了但没磨到点上。本章节定义每一轮打磨看什么、改什么、达标标准是什么。**禁止一次生成就交付。**

### 8.1 打磨轮次定义

**第1轮：结构打磨（必做）**
- **看什么**：构图结构是否符合所选模板？视觉隐喻是否统一？信息是否融入隐喻？小黑是否参与核心动作？
- **改什么**：构图跑偏→重选模板+重构prompt；隐喻不统一→重写隐喻设计卡；信息平铺→重新规划信息布局
- **达标标准**：构图骨架正确+隐喻统一+信息融入+小黑有动作

**第2轮：细节打磨（必做）**
- **看什么**：水彩质感是否有笔触有层次？数据卡片是否精致？元素之间是否有层次（不重叠不拥挤）？文字是否清晰？
- **改什么**：水彩平涂→强调"水彩有笔触有层次"；元素拥挤→调整布局增加留白；文字模糊→强调文字清晰
- **达标标准**：水彩有质感+元素精致+层次分明+文字清晰

**第3轮：精修（可选，前两轮都达标但追求定稿版水平时）**
- **看什么**：和参考图对比，细节精致度差距在哪里？有没有可以加的小细节（小黑表情/隐喻物件细节/背景小装饰）？
- **改什么**：加细节、调比例、优化颜色
- **达标标准**：达到或接近参考图水平

### 8.2 打磨checklist（每轮逐项打勾）

**结构打磨checklist（第1轮，全过才进第2轮）**：
- [ ] 构图骨架符合所选模板（不是自由发挥）
- [ ] 核心隐喻统一，所有信息都能放进隐喻
- [ ] 数据/判断/来源融入隐喻（不是贴在旁边）
- [ ] 小黑参与核心动作（不是站旁边装饰）
- [ ] 信息密度够（至少2组对比/信息点，不单薄）
- [ ] 金句/编号/来源位置正确

**细节打磨checklist（第2轮，全过才算打磨完成）**：
- [ ] 水彩填色有笔触有层次（不是平涂）
- [ ] 数据卡片精致（圆角、白字、颜色正确）
- [ ] 元素之间有层次（不重叠不拥挤不空旷）
- [ ] 文字清晰可读（无错别字、无模糊、无#色值编号）
- [ ] 颜色语义正确（橙=数据、蓝=判断、红=金句、黑=线稿）
- [ ] 小黑形象完整（圆头+白点眼+细腿+手臂+表情生动）

**精修checklist（第3轮，可选，追求定稿版水平时做）**：
- [ ] 和参考图对比，细节精致度无明显差距
- [ ] 小黑表情生动（不是呆滞）
- [ ] 隐喻物件有细节（不是简笔画）
- [ ] 整体画面有"杂志插画"质感

### 8.3 打磨达标标准

- **及格线（必须达到才能交付）**：第1轮结构打磨全过 + 第2轮细节打磨全过
- **高质量线（目标）**：及格线 + 第3轮精修全过，达到参考图水平
- **打磨上限**：结构打磨≤2次（结构不对就重构prompt，不要反复微调）；细节打磨不限次数直到达标

### 8.4 打磨方式铁律

- 画面质量不达标时**重新生成**（优化prompt），不依赖image_edit修画面（image_edit修字都不可靠，修画面更不可靠）
- 打磨时只改不达标项，不要全盘重构（避免把好的部分也改坏）
- 每轮打磨后必须重新走生成后检查（文字10项+画面质量四维度）
- 打磨过程中保留每一版，最终选最好的一版加边框交付
- **边框规格（v5.1.1 明确化 · 2026-09-08）**：正文图（16:9横版）加**黑圆角细边框**（Pillow width=10/radius=24）；封面图（3:4竖版）**不加边框**（封面需要视觉冲击力，边框会削弱）

### 12.3 image_edit 使用边界（v4.0.0保留）

**image_edit 有效的场景**：
- ✅ 去除底部注释行/说明文字
- ✅ 去除小区域不需要的元素（如多余的装饰、标签）
- ✅ 调整颜色（小范围）
- ✅ 去除水印/签名

**image_edit 无效/不稳定的场景**：
- ❌ 修正单个中文字（效果不稳定，经常改不对）
- ❌ 增加新的文字元素（容易乱码）
- ❌ 大幅度改变构图（效果不可控）
- ❌ 改变核心视觉元素（效果不可控）

**使用原则**：
- image_edit 只用于"去除"和"小范围调整"，不用于"增加"和"大幅修改"
- 中文文字错误一律用 image_gen 重新生成，不要用 image_edit 改单字
- 使用 image_edit 前，先判断是否在有效场景内，不在的话直接重新生成

### 12.4 返工上限与降级策略

**返工上限**：
- 单张图最多返工3次
- 3次仍不合格，必须停下来检查prompt设计问题，不能继续盲目生成

**降级策略**（3次仍不合格时）：
1. **简化文字**：把金句/数据卡/判断标签的文字缩短到最简（2-4字）
2. **减少文字**：去掉判断标签，只保留金句+数据卡
3. **简化隐喻**：去掉中深层隐喻，只保留表层隐喻
4. **换表达方式**：把易错字全部换成最简单的同义字
5. **回退上一版**：如果上一版可用，回退到上一版
6. **向用户说明**：如果简化后仍不合格，向用户说明情况，提供可用的简化版

## 十四、风格指南（v4.0.0保留 + v5.0.0交付形态）

### 14.1 视觉风格
- **背景**：纯白背景，不要纸纹、米色、阴影、渐变
- **线稿**：黑色手绘线稿，细线，轻微抖动
- **留白**：主体占画面60%-70%，大量留白
- **配色**：红（金句）、橙（数据）、蓝（判断）、黑（线稿/角色）、白（背景），只能用这5种颜色
- **核心原则**：一张图只表达一个核心动作、结构、状态或隐喻
- **IP角色**：小黑必须参与核心动作，不能只是装饰
- **调性**：怪诞、有创意、清爽，但不幼稚、不卖萌

### 14.2 颜色语义系统
| 颜色 | 色值 | 含义 | 使用场景 |
|------|------|------|---------|
| 🔴 红色 | #E53935 | 金句/核心观点 | 文章金句、核心判断、风险提示 |
| 🟠 橙色 | #FB8C00 | 数据/事实 | 数字、金额、统计数据、时间节点 |
| 🔵 蓝色 | #1E88E5 | 判断/分析 | 观点判断、分析结论、科技相关 |
| ⚫ 黑色 | #212121 | 线稿/文字/角色 | 线稿、文字、小黑 |
| ⚪ 白色 | #FFFFFF | 背景/留白 | 背景、留白 |

**色值使用规则**：色值只用于指定颜色，**绝对禁止作为文字内容画在图上**。

### 14.3 小黑角色设定
- **外貌**：黑色实心小圆点（直径约画面高度的1/8），两个白色小圆点眼睛，两条细黑线腿，两条细黑线手臂
- **性格**：狡黠、自信、有点腹黑、爱思考、好奇心强
- **表情库**：狡黠（眨眼+嘴角上扬）、兴奋（双眼睁大+嘴巴张开）、自信（双眼坚定+微笑）、心虚（眼神躲闪+假笑+冒汗）、顿悟（双眼发亮+灯泡）、期待（双眼诚恳+身体前倾）
- **道具库**：墨镜、工程师帽、演出服、西装、白大褂、喇叭、扳手、话筒、剧本、放大镜、方向盘
- **使用规则**：每张图必须有小黑参与核心动作，表情必须符合情感曲线，服装/道具必须符合内容类型

### 14.4 正文图统一交付形态（v5.0.0新增：加黑色圆角细边框）

**正文图最终版加黑色圆角细边框**，贴合手绘线稿风，像杂志插图描边，形成系列统一感（公众号已验证用户认可）：

- 用 Pillow 脚本统一处理（python3 + PIL，已验证可用）：
  - `rounded_rectangle` 黑色 `outline=(33,33,33,255)`，`width=10`（2048×1152 基准），`radius=24`
- 加框后重新交付验收
- 封面不加边框（封面在信息流中要的是视觉冲击，边框会削弱）

### 14.5 构图库（5种轮换使用）
| 构图类型 | 适用场景 | 视觉效果 |
|---------|---------|---------|
| **对角线** | 动态、增长、冲击 | 从左下到右上的动势 |
| **三角形** | 稳定、系统、结构 | 三点支撑 |
| **环形** | 包围、循环、关注 | 中心被包围 |
| **放射状** | 聚焦、扩散、影响 | 从中心向外辐射 |
| **对称** | 对比、选择、平衡 | 左右对称 |

> **注意**：构图库（本节）解决"画面骨架"（对角/三角/环形），构图模板库（第四节）解决"信息布局"（双组对比/路径穿越/三格漫画）。两者叠加使用：先按内容类型选信息布局模板，再在模板内用构图库设计画面骨架。

### v5.1.0 实战验证修正（2026-09-06）

**实战来源**：英伟达长文图一按v5.0.0方法论生成验证，7轮迭代（6次image_gen+1次image_edit）暴露模板真实缺陷，全部固化回skill。

**关键修正（每一条都有实测证据）**：
1. **证伪"文字后加必须准确指令"**（1.3技巧2）——括号元指令"（这5个字必须准确无误）"会被模型**画进图里**。改为**朴素写法**：文字只给准确文本，不加任何括号说明
2. **新增文字白名单铁律**（1.3技巧5）——prompt末尾必须列"整图只允许出现以下文字…除此之外禁止出现任何其他文字"。实测：白名单+朴素写法组合下，12处文字的图全部正确；不加白名单时污染严重
3. **新增章节标题泄漏规避**（1.4）——【来源】【限定】等章节标题被画成"来源：限定"；来源/限定并入【画面内容】描述，不单独开章节
4. **新增结构性词泄漏规避**（1.4）——"左组/右组"被画成"主租"；改"画面左半部分/画面右半部分"
5. **来源标注降级**（1.4/6.2）——"官方博客"→"官方微博/助力博睿""英伟达官网"→"英迪进入官网"反复错字。**头条正文图默认不画来源**（五层核对的来源层保留为生成前核对，来源在图注/正文体现）；必须画时用最短形式"NVIDIA"
6. **负面词"#"字面修正**——"绝对不要写任何#开头的色值编号"中的#会被画出来（图上出现"# NVIDIA"），改"绝对不要出现任何井号符号和颜色代码"
7. **防自动加标点**——"还没赚钱"被加感叹号/问号，负面词加"文字后面不要加标点符号"
8. **背景强调纯白**——不强调时模型给浅米色底，改为"背景必须是纯白色，不能是米色、浅黄或灰底"
9. **验证image_edit去小区域文字有效**——去除左下角来源行成功；再次确认改单字不可靠
10. **返工纪律实战验证**——7轮中第6轮最佳，第7轮反而退化（结构合并+新错字）。印证"3次文字返工后停止盲目重试，回退最佳版本+定向修复"

### v5.0.0 核心升级（2026-09-06）

**实战来源**：公众号配图体系（gzh-illustration v1.3.4，H20/GPT-6 Astra等多篇，20+轮迭代验证）与头条v4.0.0（英伟达收购HF长文3轮迭代）融合。

**核心思路**：v4.0.0解决了"文字错字、封面平淡、隐喻太浅"三个表层问题，但质量仍不稳定——根因是**每次画图都从零自由发挥，没有"已知的好"作为锚点**。v5.0.0建立六大质量锚点，让"超高质量"从碰运气变成每次可复现。

**新增模块**：
1. **段落骨架五层核对法**（第二节，正文图硬门槛）——数据/来源/性质/判断/限定五层，缺一层不合格，"只能高不能低"；来源标注规范（灰色小字）
2. **视觉隐喻设计卡**（第三节）——写prompt之前必做（核心隐喻/构图模板/信息布局/小黑动作/参考图/水彩质感），设计卡缺失=禁止生成
3. **构图模板库**（第四节）——从公众号定稿版提炼5种高质量构图模板（双组并排对比/路径穿越隐喻/三格漫画演变/左右分割隐喻/角色演变清单），每种有骨架/适用场景/元素布局/参考图
4. **内容类型→模板映射+决策树**（第五节）——10种内容类型→首选/备选模板+5步决策树+模板扩展机制（用户确认才能入库）
5. **封面钩子三法+封面构图模板**（第七节）——反常识划掉法/对比冲突法/大数字钩子法+封面A/B/C三型，封面SOP升级为7步
6. **打磨SOP标准化**（第八节）——三轮打磨定义（结构/细节/精修）+每轮checklist+达标标准，"禁止一次生成就交付"
7. **画面质量四维度评估**（第十二节）——视觉隐喻设计感/信息密度/构图结构/元素融合度，文字对只是及格线，四维度全过才是交付线
8. **来源标注必选**（第九节）——11项必选元素，正文图必须有来源标注（灰色小字）
9. **正文图统一交付形态**（第十四节）——加黑色圆角细边框（Pillow），封面不加
10. **参考图资产**（第十七节）——6张参考图入库（5张正文模板+1张头条封面），参考图积累机制

**升级模块**：
11. **Prompt正文模板**（第六节）——从"元素清单"升级为"构图骨架→核心隐喻→信息填充→小黑动作"，生成必须传参考图
12. **生成前检查清单**（第十节）——15项升级为18项（新增五层核对/参考图/来源标注）
13. **生成后验收清单**（第十一节）——15项升级为17项（新增五层骨架核对/来源标注）
14. **质量评估标准**（第十五节）——新增构图结构/来源标注两个评估项，总分40分

**保留模块**（v4.0.0精华完整保留）：
