## 🚨 执行铁律（每次调用必读，违反视为违规）

> **本skill的核心不是"方法论"，而是"纪律"。方法论写得再好，Agent不执行=0。**

### 每次画图，必须严格执行以下三步，缺一不可：

**第1步：画前重读（禁止凭记忆）**
- 调用本skill后，必须先重新读取下方「10项必选元素清单」和「中文文字防错系统」
- 禁止只凭记忆或印象生成，必须基于刚读到的清单逐项组织prompt
- 即使上次刚画过，每次调用都必须重读（上下文会滚动压缩，记忆不可靠）

**第2步：画前打勾（生成前逐项确认）**
- 生成图片前，必须把10项必选元素**逐项列出并写进prompt**
- 同时必须执行「中文文字防错检查」（见第一节）
- 检查清单全部打勾后才允许调用生图工具

**第3步：画后验收（生成后逐项对照）**
- 图片生成后，必须对照验收清单逐项检查
- **中文文字必须逐字核对**（这是v4.0.0新增的最高优先级验收项）
- 任何一项缺失或错误，立即按「返工策略库」针对性修正
- 返工最多3次，仍不合格必须停下来重新检查prompt设计问题
- 每张图验收通过后，向用户明确标注"已按skill v4.0.0标准验收"

**违规示例（明令禁止）**：
- ❌ 不重读skill直接生成
- ❌ 凭印象生成，漏掉小黑/颜色/风格
- ❌ 生成后发现中文错字但嫌麻烦不返工
- ❌ 用"差不多就行"的心态验收
- ❌ 在prompt中写注音说明/字形拆解（会被画进图里）

## 一、中文文字防错系统（v4.0.0新增，最高优先级）

> **为什么这是最高优先级**：v3.1.1在实战中中文文字错字率超过60%。"卖铲子"→"卖骰子"→"卖锚子"（连续3次才成功）、"留心眼"→"真心眼"、"难"→"滩"、"分发权"→"分股权"、"2027交割见分晓"→"交职院分晚"。生图模型（seedream）对中文字符的生成能力有限，这是硬限制，必须通过方法论适配。

### 1.1 易错字黑名单（生成前必须检查）

以下字/词在生图模型中极易写错，prompt中出现时必须特别处理：

| 易错字/词 | 常见错误 | 处理方式 |
|-----------|---------|---------|
| 铲子 | 骰子、锚子、铲子 | 避免使用，改用"工具""家伙" |
| 留心眼 | 真心眼 | 避免使用，改用"多留神""要小心" |
| 难（结尾） | 滩、摊 | 避免在句尾单独用"难"，改用"不容易""不简单" |
| 分发权 | 分股权、分配权 | 避免使用，改用"说了算""有话语权" |
| 管矿 | 管广、管矿 | 避免使用，改用"管矿山""做矿主" |
| 交割 | 交职、交割 | 避免使用，改用"完成""落地" |
| 见分晓 | 分晚、分晓 | 避免使用，改用"见结果""看结局" |
| 承诺 | 承落、承诺 | 可用，但需在prompt中强调 |
| 开放 | 开方、开放 | 可用，但需在prompt中强调 |
| 收购 | 收够、收购 | 可用，但需在prompt中强调 |
| 算力 | 算利、算力 | 可用，但需在prompt中强调 |
| 开发者 | 开法者、开发者 | 可用，但需在prompt中强调 |

**核心原则**：能不用易错字就不用，改用同义的简单字。金句/数据卡/判断标签的文字必须经过"易错字检查"后才能写入prompt。

### 1.2 文字长度限制（硬性约束）

生图模型对短文字的生成准确率远高于长文字。必须遵守：

| 文字类型 | 最大长度 | 推荐长度 | 示例 |
|---------|---------|---------|------|
| 金句（红色） | 8字 | 4-6字 | "买了个承诺""从卖铲子到管矿" |
| 数据卡（橙色） | 6字 | 2-4字 | "129.3亿""1800万""3倍" |
| 判断标签（蓝色） | 6字 | 2-4字 | "史上第二""拒绝收购难"→改为"不容易" |
| 编号（左上角） | 2字 | 1字 | "一""二""封面" |
| 封面主标题 | 10字 | 6-8字 | "877亿买了个承诺" |

**超过长度的文字必须拆分或简化**。例如"2027年上半年交割见分晓"→拆为数据卡"2027"+判断标签"待审批"。

### 1.3 Prompt 逐字强调技巧（核心方法论）

当必须使用可能易错的文字时，在prompt中使用以下技巧提高准确率：

**技巧1：文字单独成段，不与视觉描述混在一起**
```
❌ 错误写法：
画面中间有一个橙色数据卡片，上面写着"129.3亿美元"，旁边有小黑指着它

✅ 正确写法：
画面中间有一个橙色圆角矩形数据卡片。
卡片上的文字是：129.3亿
（文字必须清晰、准确、无错别字）
```

**技巧2：文字后加"必须准确"指令**
```
红色手写体金句，文字内容是：买了个承诺
（这4个字必须准确无误，每个字都要写对）
```

**技巧3：避免在同一张图中出现过多文字**
- 每张图最多3处文字（1金句+1数据卡+1判断标签）
- 文字越少，准确率越高
- 目录导览等长文字**禁止出现在封面**（实战中100%乱码）

**技巧4：数字用阿拉伯数字，不用中文数字**
```
❌ "一百二十九亿三千万美元"
✅ "129.3亿"
```

### 1.4 固定乱码模式库（已知问题，必须规避）

以下是seedream模型的固定乱码模式，prompt中必须规避：

| 模式 | 表现 | 规避方法 |
|------|------|---------|
| "8%" | 任何包含"8%"的文字都会乱码 | 避免使用"8%"，改用"8个百分点"或纯数字"8" |
| 目录导览 | 封面底部的5个小标题100%乱码 | 封面禁止目录导览，改用3个数据卡横排 |
| 注音说明 | prompt中写"XX字，读YY"会被画进图里 | 绝对禁止在prompt中写注音/拼音/字形拆解 |
| 色值编号 | "#FB8C00"会被画在卡片上 | 色值只用于指定颜色，禁止作为文字内容 |
| 长句金句 | 超过8字的金句错字率>80% | 金句控制在6字以内 |

### 1.5 文字生成失败的修正策略

| 失败类型 | 表现 | 修正方法 |
|---------|------|---------|
| 单字错误 | "铲子"→"骰子" | 换同义字（"工具"），或在prompt中逐字强调 |
| 多字乱码 | "见分晓"→"分晚" | 缩短文字或拆分 |
| 完全不显示 | 金句位置空白 | 检查prompt中金句是否单独成段，重新生成 |
| 元信息泄漏 | 图底部出现注音说明 | 删除prompt中的所有注音/拼音/字形拆解说明 |
| 数字错误 | "129.3亿"→"1293亿" | 用阿拉伯数字+单位，在prompt中强调小数点 |

## 三、封面竞争力设计（v4.0.0新增）

> **为什么封面需要独立方法论**：封面在头条信息流中的竞争逻辑与正文配图完全不同。封面只有3秒抓眼球的机会，正文配图是辅助阅读。v3.1.1把两者用同一套方法论，导致封面太平淡（第一版封面"两扇门+钥匙"被用户否决）。

### 3.1 头条封面规范（3:4竖版）

| 项目 | 规范 | 理由 |
|------|------|------|
| 比例 | 3:4竖版 | 头条信息流大图卡片，3:4展示面积最大，最抓点击 |
| 尺寸 | 1536x2048 | 3:4的标准高清尺寸 |
| 安全区域 | 中心1200x1600 | 重要信息放在中心，边缘留裁剪空间 |
| 文字数量 | 最多3处（1主标题+2数据卡） | 文字越少越抓眼，错字率越低 |
| 主标题长度 | ≤10字 | 信息流中一眼能读完 |
| 数据卡数量 | 1-3个横排 | 用数字制造冲击力 |

### 3.2 封面三要素（缺一不可）

**要素1：视觉冲击（第一眼抓住）**
- 必须有一个"大到占画面40%以上"的核心视觉元素
- 必须有动态感（手在撕、门在开、雪球在滚）
- 必须有颜色对比（红金撞色、明暗对比）
- 反例：两扇门+钥匙（静态、平淡、无冲击）
- 正例：巨手撕告示+门缝金光（动态、冲突、有冲击力）

**要素2：反常识钩子（让人想点）**
- 主标题必须是反常识/有悬念/有冲突的判断
- 不是"英伟达收购Hugging Face"（新闻标题，没人想点）
- 而是"877亿买了个承诺"（反常识，让人想点进去看"什么承诺"）
- 钩子公式：大数字+反常识判断 = 点击欲

**要素3：数据背书（建立可信度）**
- 1-3个数据卡横排在画面底部或中部
- 数据必须是文章中最有冲击力的数字
- 例如："129.3亿""1800万开发者""3年涨3倍"
- 数据卡用橙色，与红色主标题形成颜色层次

### 3.3 封面竞争力检查清单

生成封面后，必须逐项检查：

- [ ] **1. 3秒测试**：遮住标题，只看画面，3秒内能猜出文章主题吗？
- [ ] **2. 视觉冲击**：核心元素占画面40%以上吗？有动态感吗？
- [ ] **3. 反常识钩子**：主标题是反常识/有悬念的判断吗？不是新闻标题吧？
- [ ] **4. 数据背书**：有1-3个数据卡吗？数据是文章中最有冲击力的吗？
- [ ] **5. 颜色对比**：有红金撞色或明暗对比吗？不是平淡的单色吧？
- [ ] **6. 文字准确**：主标题和数据卡的文字逐字核对了吗？没有错字吧？
- [ ] **7. 无目录导览**：封面没有目录导览吧？（实战中100%乱码）
- [ ] **8. 小黑参与**：小黑有参与核心动作吗？不是装饰吧？
- [ ] **9. 3:4竖版**：尺寸是3:4竖版吗？不是16:9横版吧？
- [ ] **10. 信息流测试**：想象这张封面出现在头条信息流里，你会点吗？

### 3.4 封面设计模板库

**模板A：手撕型（适合收购/合并/决裂类题材）**
- 核心视觉：一只大手正在撕某物（告示/合同/大门）
- 动态感：撕的动作+被撕物的裂缝+裂缝透出的光
- 主标题："[大数字]买了个[反常识词]"
- 数据卡：交易金额+被收购方规模+估值涨幅

**模板B：雪球型（适合增长/复利/滚雪球类题材）**
- 核心视觉：一个小雪球从山坡滚下，变成巨大雪球
- 动态感：滚动轨迹+越来越大的雪球+飞溅的碎片
- 主标题："[小数字]→[大数字]，[时间]翻了[倍数]"
- 数据卡：起点数字+终点数字+涨幅倍数

**模板C：钥匙型（适合控制权/话语权/选择权类题材）**
- 核心视觉：左边钥匙挂在别人腰间，右边铁砧上自己打造钥匙
- 对比感：左右对称+依赖vs自主的对比
- 主标题："[反常识判断]，钥匙在谁手里？"
- 数据卡：依赖方规模+自主方进展+时间节点

**模板D：特洛伊木马型（适合陷阱/伪装/表里不一类题材）**
- 核心视觉：一个告示牌/礼物盒，裂缝里透出大锁/芯片/钩子
- 悬念感：表面美好+内里隐藏的危险
- 主标题："[表面好词]背后，藏着[反面词]"
- 数据卡：表面规模+隐藏代价+时间节点

**模板E：窗桥型（适合危机/转机/破局类题材）**
- 核心视觉：一扇门关了，但墙上有窗；路跨深沟变成桥；脚印旁有火把
- 希望感：困境中的出路+后来人的指引
- 主标题："关了一扇门，开了[数字]扇窗"
- 数据卡：困境规模+出路数量+时间节点

## 四、隐喻设计方法论（v4.0.0新增）

> **为什么隐喻需要独立方法论**：v1版配图只有表层隐喻（时间轴、卖铲子vs管矿），v3版增加2-3层隐喻后用户说"好了很多"。但v3.1.1只有"多层隐喻系统"的概念，没有具体的设计方法。v4.0.0把隐喻设计从"灵感"变成"可复用的方法论"。

### 4.1 统一隐喻主线设计法

**一套配图（封面+5张正文）必须有一条统一的隐喻主线**，所有图都围绕这条主线展开，而不是每张图各用各的隐喻。

**设计步骤**：
1. **提炼文章核心冲突**：这篇文章最核心的矛盾是什么？（收购=买入口vs保持开放、增长=滚雪球、控制=钥匙在谁手里）
2. **选择核心隐喻**：用一个日常场景来类比这个冲突（买入口=修路/收收费站、增长=滚雪球、控制=钥匙）
3. **设计隐喻递进**：5张正文图的隐喻要有递进关系，不是重复
   - 图1：隐喻的起点（小雪球/小摊贩/旧钥匙）
   - 图2：隐喻的发展（大雪球/收费站/别人的钥匙）
   - 图3：隐喻的转折（雪球失控/收费站关门/钥匙被收）
   - 图4：隐喻的对比（别人的路vs自己的路/依赖vs自主）
   - 图5：隐喻的升华（路越走越宽/自己造钥匙/火把照亮后来人）
4. **封面用隐喻的高潮**：封面是整套图的视觉高潮，用隐喻中最有冲击力的瞬间

**示例（英伟达收购HF长文）**：
- 核心冲突：买入口vs保持开放
- 核心隐喻：门与路（买门=控制入口，修路=自主可控）
- 递进：
  - 图1：滚雪球（45亿→129.3亿，估值暴涨）
  - 图2：淘金热→收费站→控制室（做生意→收税→掌控）
  - 图3：特洛伊木马+鱼钩（告示牌裂缝里的大锁+开放诱饵）
  - 图4：钥匙隐喻（别人腰间vs自己打造）
  - 图5：窗+桥+火把（关了门有窗、路跨沟变桥、火把照亮后来人）
- 封面：巨手撕"保持开放"告示+门缝金光（隐喻的高潮）

### 4.2 三层隐喻叠加法

每张图应同时包含2-3层隐喻，从浅到深：

**表层隐喻（直观可见，读者一眼看懂）**
- 用日常场景类比文章内容
- 例如：滚雪球=估值暴涨、收费站=收算力税、钥匙=控制权
- 表层隐喻必须是读者熟悉的日常事物，不能太抽象

**中层隐喻（需要思考，读者思考后能领悟）**
- 在表层隐喻中加入第二层含义
- 例如：雪球上写着"45亿"滚成"129.3亿"=不仅是滚雪球，还是资本的力量
- 收费站上写着"算力税"=不仅是收费站，还是平台的抽成
- 中层隐喻让图有"品"的空间，不是一眼看完

**深层隐喻（时代镜像，增加深度）**
- 在背景中加入淡灰色文字或符号，暗示时代主题
- 例如：背景隐约有"AI时代""人人都是参与者""注意力经济"等淡灰色文字
- 深层隐喻不抢主体，但让图有厚度
- **注意**：深层隐喻的文字也必须经过中文防错检查，且必须非常淡（灰色，不仔细看看不清）

**叠加原则**：
- 表层隐喻必须清晰，不能为了中深层而让表层看不懂
- 中层隐喻最多1-2个，不能太多
- 深层隐喻是可选的，时间不够可以不加
- 三层隐喻不能互相冲突，必须围绕统一隐喻主线

### 4.4 隐喻设计检查清单

- [ ] **1. 统一主线**：整套配图（封面+正文）有一条统一的隐喻主线吗？
- [ ] **2. 递进关系**：5张正文图的隐喻有递进关系吗？不是重复吧？
- [ ] **3. 表层清晰**：每张图的表层隐喻是读者熟悉的日常事物吗？一眼能看懂吗？
- [ ] **4. 中层有品**：每张图有1-2个中层隐喻吗？让读者有"品"的空间吗？
- [ ] **5. 深层可选**：深层隐喻是可选的，没有为了加而加吧？

- [ ] **7. 封面高潮**：封面用了隐喻中最有冲击力的瞬间吗？
- [ ] **8. 小黑参与**：小黑在隐喻中有角色吗？不是旁观者吧？
- [ ] **9. 文字适配**：金句/数据卡/判断标签的文字与隐喻匹配吗？
- [ ] **10. 读者测试**：遮住文章，只看配图，能猜出文章的核心冲突吗？

| **构图拥挤** | 元素重叠/画面太满 | ①减少元素数量 ②在prompt中强调"大量留白" ③重新生成 | image_gen |
| **底部注释行** | 图底部多了一行说明文字 | ①用image_edit去除底部注释行 ②或重新生成 | **image_edit（有效）** |
| **小区域元素去除** | 图中有不需要的小元素 | ①用image_edit去除该元素 ②或重新生成 | **image_edit（有效）** |
| **单个中文字修正** | 图中只有一个字错了 | ❌ **image_edit效果不稳定，不推荐** ①重新生成 ②或换同义字 | image_gen |
| **封面吸引力不足** | 封面太平淡 | ①按封面竞争力设计重新设计 ②用封面设计模板 ③重新生成 | image_gen |
| **隐喻不够深** | 图只有表层隐喻 | ①按隐喻设计方法论增加中层隐喻 ②重新生成 | image_gen |

### 8.2 image_edit 使用边界（v4.0.0明确定义）

**image_edit 有效的场景**：
- ✅ 去除底部注释行/说明文字
- ✅ 去除小区域不需要的元素（如多余的装饰、标签）
- ✅ 调整颜色（小范围）
- ✅ 去除水印/签名

**image_edit 无效/不稳定的场景**：
- ❌ 修正单个中文字（效果不稳定，经常改不对）
- ❌ 增加新的文字元素（容易乱码）
- ❌ 大幅度改变构图（效果不可控）
- ❌ 改变核心视觉元素（效果不可控）

**使用原则**：
- image_edit 只用于"去除"和"小范围调整"，不用于"增加"和"大幅修改"
- 中文文字错误一律用 image_gen 重新生成，不要用 image_edit 改单字
- 使用 image_edit 前，先判断是否在有效场景内，不在的话直接重新生成

### 8.3 返工上限与降级策略

**返工上限**：
- 单张图最多返工3次
- 3次仍不合格，必须停下来检查prompt设计问题，不能继续盲目生成

**降级策略**（3次仍不合格时）：
1. **简化文字**：把金句/数据卡/判断标签的文字缩短到最简（2-4字）
2. **减少文字**：去掉判断标签，只保留金句+数据卡
3. **简化隐喻**：去掉中深层隐喻，只保留表层隐喻
4. **换表达方式**：把易错字全部换成最简单的同义字
5. **回退上一版**：如果上一版可用，回退到上一版
6. **向用户说明**：如果简化后仍不合格，向用户说明情况，提供可用的简化版

### 8.4 常见错误速查表

| 错误 | 快速修正 |
|------|---------|
| "卖铲子"错了 | 改成"卖工具"或"卖家伙" |
| "留心眼"错了 | 改成"多留神"或"要小心" |
| "难"在句尾错了 | 改成"不容易"或"不简单" |
| "分发权"错了 | 改成"说了算"或"有话语权" |
| "见分晓"错了 | 改成"见结果"或"看结局" |
| "交割"错了 | 改成"完成"或"落地" |
| 目录导览乱码 | 封面禁止目录导览，改用3个数据卡横排 |
| "8%"乱码 | 改成"8个百分点"或纯数字"8" |
| 底部出现注音说明 | 删除prompt中的所有注音/拼音/字形拆解 |
| 卡片上出现#FB8C00 | 检查prompt，色值只用于指定颜色，不作为文字内容 |

## 十、风格指南（精简版）

### 10.1 视觉风格
- **背景**：纯白背景，不要纸纹、米色、阴影、渐变
- **线稿**：黑色手绘线稿，细线，轻微抖动
- **留白**：主体占画面60%-70%，大量留白
- **配色**：红（金句）、橙（数据）、蓝（判断）、黑（线稿/角色）、白（背景），只能用这5种颜色
- **核心原则**：一张图只表达一个核心动作、结构、状态或隐喻
- **IP角色**：小黑必须参与核心动作，不能只是装饰
- **调性**：怪诞、有创意、清爽，但不幼稚、不卖萌

### 10.2 颜色语义系统
| 颜色 | 色值 | 含义 | 使用场景 |
|------|------|------|---------|
| 🔴 红色 | #E53935 | 金句/核心观点 | 文章金句、核心判断、风险提示 |
| 🟠 橙色 | #FB8C00 | 数据/事实 | 数字、金额、统计数据、时间节点 |
| 🔵 蓝色 | #1E88E5 | 判断/分析 | 观点判断、分析结论、科技相关 |
| ⚫ 黑色 | #212121 | 线稿/文字/角色 | 线稿、文字、小黑 |
| ⚪ 白色 | #FFFFFF | 背景/留白 | 背景、留白 |

**色值使用规则**：色值只用于指定颜色，**绝对禁止作为文字内容画在图上**。

### 10.3 小黑角色设定
- **外貌**：黑色实心小圆点（直径约画面高度的1/8），两个白色小圆点眼睛，两条细黑线腿，两条细黑线手臂
- **性格**：狡黠、自信、有点腹黑、爱思考、好奇心强
- **表情库**：狡黠（眨眼+嘴角上扬）、兴奋（双眼睁大+嘴巴张开）、自信（双眼坚定+微笑）、心虚（眼神躲闪+假笑+冒汗）、顿悟（双眼发亮+灯泡）、期待（双眼诚恳+身体前倾）
- **道具库**：墨镜、工程师帽、演出服、西装、白大褂、喇叭、扳手、话筒、剧本、放大镜、方向盘
- **使用规则**：每张图必须有小黑参与核心动作，表情必须符合情感曲线，服装/道具必须符合内容类型

### 10.4 构图库（5种轮换使用）
| 构图类型 | 适用场景 | 视觉效果 |
|---------|---------|---------|
| **对角线** | 动态、增长、冲击 | 从左下到右上的动势 |
| **三角形** | 稳定、系统、结构 | 三点支撑 |
| **环形** | 包围、循环、关注 | 中心被包围 |
| **放射状** | 聚焦、扩散、影响 | 从中心向外辐射 |
| **对称** | 对比、选择、平衡 | 左右对称 |

## 十一、质量评估标准（精简版）

| 评估项 | 5分标准 | 3分标准 | 1分标准 |
|--------|---------|---------|---------|
| **中文文字准确性** | 所有文字逐字核对无错字、无乱码 | 有1处小错字但不影响理解 | 多处错字或乱码 |
| **信息密度** | 包含1核心+2-3辅助信息点，图文精准对应 | 包含2-3个信息点，基本对应 | 包含1-2个信息点，对应不准 |
| **视觉层次** | 核心突出，三级层级分明，引导视线 | 核心较突出，两级层级 | 无层次，信息散乱 |
| **隐喻深度** | 有2-3层隐喻，围绕统一主线，有递进 | 有表层隐喻，主线基本统一 | 无隐喻或隐喻混乱 |
| **角色表现力** | 小黑表情动作有故事感，参与核心动作 | 小黑有表情动作 | 小黑无表情，像装饰 |
| **逻辑连接** | 箭头/流程清晰，因果关系明确 | 有箭头但逻辑一般 | 无逻辑连接 |
| **系列一致性** | 编号/标识/风格/隐喻完全统一 | 基本统一 | 不统一 |
| **封面竞争力（封面）** | 视觉冲击+反常识钩子+数据背书，信息流中会点 | 有一定吸引力但不够强 | 平淡，不会点 |

**合格线**：每项≥4分，总分≥32分。**中文文字准确性是硬性门槛，低于4分必须返工。**
