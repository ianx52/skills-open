# 多轮吵架圆桌辩论 · Round Table Debate v2.3

> "和气讨论是观点的人工培育——每个观点都被小心翼翼保护，最后出来一个谁都不得罪但谁都不满意的杂交品种。"
> "吵架是观点的自然选择——弱观点被杀死，强观点活下来并变得更强，最后出来一个经过生存考验的、有生命力的决策。"

---

## 一、核心理念

### 辩论的本质是什么？

不是"多个人一起说话"，是**观点的自然选择**。

```
弱观点 ──被攻击──→ 暴露漏洞 ──→ 被杀死（或修正后变强）
强观点 ──被攻击──→ 经受考验 ──→ 活下来并变得更强
```

### 什么时候用 / 不用

**用**：重大决策、方案评审、争议性话题、需要可执行方案。

**不用**：①事实性问题（有明确答案直接查）；②简单选择（A或B没争议直接选）；③情绪性问题（吵架只会激化情绪）。

---

## 二、角色选择原则

1. **5-8个角色**，不超过8个
2. **至少覆盖4维度**：数据/实操、用户/受众、战略/全局、约束/当事人
3. **必须有反对派**——专门唱反调、质疑一切
4. **必须有第一人称当事人**——说"我做不到因为X"
5. **视角不重复、立场有冲突**——确保至少有两个角色在核心问题上立场根本对立（一个说做，一个说不做），不是温和的不同角度补充。没有真正的对立，讨论就变成"不同角度的补充说明"，弱观点杀不死

参考角色池（示例，不是必须从这里选）：数据分析师、资深从业者、平台/算法专家、普通用户、战略顾问、实战派、当事人、反对派、财务/成本、心理学/行为学。**根据主题现场设计，不要硬套。**

## 三、四轮辩论状态机

### 状态流转

```
初始 → [陈述] → [攻击] → [辩护+深辩] → [最终立场] → [统一质量门] → 结束
         ↑          |          |              |            |
         └──────────┴──────────┴──────────────┴────────────┘
           （质量门不通过则退回对应轮次）
```

### 每轮进入/退出条件

| 轮次 | 目标 | 退出条件 | 不通过怎么办 |
|------|------|---------|------------|
| 陈述 | 亮观点 | 每个角色都说了核心观点 | 有人没说→逼他说 |
| 攻击 | 暴露盲点 | 每个角色至少攻击1人，攻击符合高质量特征 | 不具体→打回；没人攻击→主持人指定 |
| 辩护+深辩 | 弱观点被杀死/修正，强观点被锤炼 | 2-3个核心分歧都有正反深辩，有共识和剩余分歧 | 跑题→拉回；兜圈子→问"核心分歧是什么" |
| 最终立场 | 给出经过辩论后的判断 | 每个角色给出最终立场（必须说改变了什么、为什么） | 有人说"我都同意"→逼他有自己的判断 |
| 统一质量门 | 确保过程和结果都过关 | 5项全过（见 §五） | 哪项不过退回对应轮次 |

### 第一轮：陈述（默认每人一句话核心观点，≤50字）

- 只说自己的观点，不评价别人
- 必须说"我认为什么"，不能说"有人认为什么"
- 详细版才每人说2-3段（≤300字）
- **可选**：辩论开始前问用户"你自己的初步判断是什么？"——用户愿意说就作为基准，不说就用"常见做法/行业默认"做基准
- **主题质量快速判断（v2.3.1新增）**：陈述结束后，主持人快速判断——如果发现"大家都同意、没分歧、没东西可吵"，立即暂停，建议用户换主题或缩小范围。好主题的三个特征：有明确决策指向、有真实立场冲突、有可执行输出预期。主题不好，四轮辩论也救不了。

### 第二轮：攻击（必须符合高质量攻击特征，见 §四）

- 每个角色至少攻击1人，最多3人
- 被攻击的人这一轮不辩护
- 攻击角度参考：数据质疑、逻辑漏洞、前提错误、忽略约束、幸存者偏差、站着说话不腰疼、过时信息、以偏概全

### 第三轮：辩护+深辩

- 辩护+反击，核心分歧深辩（2-3个）
- 可以部分承认："你这一点对，我修正；但那一点你错了"
- 被驳倒了就承认，死不认错最丢人
- **去极化环节（详细版才展示，默认输出跳过）**：每个角色说"对方观点中最有道理的一点是___"

### 第四轮：最终立场

- 每个角色必须说："我之前认为X，现在认为Y，因为Z"
- 主持人给出综合决策方案：每个分歧点明确选择+为什么；没共识的承认剩余分歧+分支方案；可执行行动方案+时间线+风险
- **最后必须问用户**："你是否认同？不认同哪个点？我可以只辩那个点再来一轮"

---

## 四、高质量攻击/深辩特征（判断标准）

### 高质量攻击4特征（缺一个就是低质量）

1. **指出对方具体哪个观点**——不是"你不对"，是"你说的'7天洗标签'这个观点有问题"
2. **有论据/数据/逻辑支撑**——不是"我觉得不对"，是"因为XX数据/XX逻辑，所以不成立"
3. **击中对方观点的前提或推理链**——不是攻击结论，是攻击前提假设或推理跳步
   - **可执行验证**：先识别对方观点的前提——"对方说X，X成立的前提是Y"；攻击针对Y就是击中前提，针对X就是攻击结论
4. **能引发对方修正或承认**——攻击完，对方需要修正或承认，而不是重复原观点反驳

### 高质量深辩4特征

1. 双方都有新论据（不是重复第一轮）
2. 分歧收敛（从"要不要"到"怎么做/什么时候"）
3. 共识部分被明确识别
4. 剩余分歧被清晰界定（"我们的分歧是X，不是Y"）

## 五、统一质量门5项（v2.3核心：三层元认知合并为一层）

> **为什么合并**：v2.2有三层元认知（质量自检5项+结果评估3项+价值证明），认知科学研究表明多层元认知准确率指数级递减，三层叠加不如一层认真的检查。v2.3合并为5项，覆盖过程质量和结果质量，认知负荷降低60%以上。

最终立场后、输出结论前，逐项验证。**前3项客观验证不通过必须退回对应轮次，后2项主观判断不通过提醒后修正。**

| # | 检查项 | 验证方法 | 不通过退回 |
|---|--------|---------|-----------|
| 1 | **信息增量（量）** | 列出本轮新引入的3个论据/角度/约束，每个必须说明"这是上一轮没有的"。表述不同≠观点不同，必须是新信息不是新说法。这一项检查的是"有没有新东西"（数量维度） | 退回攻击轮 |
| 2 | **攻击质量** | 所有攻击都：①指出了具体观点；②有论据；③击中前提或推理链（不是只攻击结论）。缺一个=低质量攻击 | 退回攻击轮 |
| 3 | **暴露盲点（质）** | 新引入的信息中，至少有1个是"之前被忽略的关键问题/关键约束/关键角度"。**验证方法**：问自己"这个发现如果被忽略，决策会有什么不同？"——如果没什么不同，就不是重要发现；如果会改变决策方向，就是重要发现。这一项检查的是"新东西重不重要"（质量维度），和第1项的"有没有新东西"不同 | 退回深辩轮 |
| 4 | **结论可执行** | 有具体行动（不是"要提升质量"）+ 有时间线 + 有明确下一步（用户看完知道明天干什么）。缺一个=不可执行 | 退回深辩轮 |
| 5 | **覆盖关键约束** | 时间/能力/资源/风险四个约束都被考虑到了。有一个被忽略=不完整 | 退回深辩轮 |

**额外验证（软规则，不通过不重来）**：结论有没有超出"常见做法/行业默认"的范围？如果没有，说明辩论没带来增量价值，标注"价值待验证"后输出。

## 六、输出格式（默认精简，2000字以内）

> **⚠️ 输出术语红线（v2.3.1新增）**：用户看到的输出中**禁止出现skill内部概念术语**——包括但不限于"质量门""元认知""观点自然选择""去极化""统一质量门""信息增量""暴露盲点"。用户看到的应该是"讨论结果""核心分歧""决策方案"，不是辩论机制术语。这些术语只在skill内部（给AI看的）使用，输出给用户时必须翻译成用户能理解的语言。

```
【讨论主题】
【参与角色】（5-8个，标注视角）

【关键讨论点】（合并观点背景+核心攻击，精简版）
- 每个角色一句话核心观点（≤50字）
- 最有价值的2-3个攻击点（只记击中要害的，不罗列所有）

【决策方案】
一、核心结论
二、关键决策（选了什么、为什么）
三、行动方案（具体、有时间线）
四、风险提示
五、剩余分歧（承认它，给分支方案）

【这场讨论的价值】（必须具体到某个人/某个事/某个数据，空话不算）
- 暴露了什么之前被忽略的问题
- 修正了什么错误判断
- 逼出了什么实操手段
（不够具体就标注"价值待验证"，不是必须重来）

【你怎么看？】
你是否认同？不认同哪个点？我可以只辩那个点再来一轮。
```

详细版（用户说"详细版"才触发）：完整四轮过程+去极化环节+所有攻击和深辩。

## 七、异常处理

| 异常 | 处理 |
|------|------|
| 第二轮没人攻击 | 主持人指定："A，你对B的观点有没有质疑？" |
| 攻击不具体 | 打回："具体哪个观点不对？为什么？有什么论据？" |
| 攻击不符合高质量特征 | 对照 §四 4个特征重新攻击 |
| 第三轮跑题 | 介入："回到核心分歧X" |
| 双方兜圈子 | 介入："有没有新论据？没有就下一个分歧" |
| 被驳倒了死不认错 | 介入："你能不能承认这一点你错了？不丢人" |
| 第四轮有人说"我都同意" | 打回："你必须有自己的判断" |
| 质量门不通过 | 退回对应轮次（见 §五 表格） |
| 四轮后完全没共识 | 承认剩余分歧，给分支方案，不要假装有共识 |
| 用户不认同最终决策 | 用户指定某个分歧点，只辩那个点再来一轮 |

## 八、版本迭代与收敛判断

每使用5次后记录一次：哪些环节质量高/低、用户反馈、新异常。

**迭代收敛判断**：每3次使用后，检查核心机制是否还在变化——如果连续3次没有大的机制改动，说明已经收敛，可以冻结版本。防止无限迭代。

重大改动（核心机制变化）升级次版本号（v2.x→v3.0）。
